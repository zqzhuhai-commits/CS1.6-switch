# 欢乐谷实体绘制隔离测试 04

用户真机反馈：补丁 01、02、03 均未消除花屏；`r_drawentities 0` 后不再花屏。这将范围缩小至实体相关的绘制，但不能单独证明某种材质、着色器或透明效果存在错误。

本包增加一张独立地图 `happyvalley_lt_solid.bsp`，基于用户参考包的 `happyvalley_lt.bsp` 生成。将 110 个可见刷子实体的非普通渲染模式改为普通不透明模式，隔离透明裁切、纹理混合与叠加发光路径。原来不可见的实体保持不变；水面纹理自身的特殊处理未移除。

几何、贴图、光照、碰撞、可见性及其他非实体数据均保持逐字节一致。实体区只改变 110 个渲染模式数字，所有模型、位置、移动逻辑、目标名称和触发器均保留。半透明物件会变为不透明，围栏等裁切材质可能出现实色背景，这是本次隔离测试的预期变化，不是最终画面效果。尚未经过真机验证。

## 测试方法

1. 完全退出游戏。将包内 `switch` 文件夹复制到 SD 卡根目录；它只新增测试地图，不覆盖原地图和现有配置。
2. 启动游戏。在本地控制台先恢复实体绘制：`r_drawentities 1`。
3. 输入 `map happyvalley_lt_solid` 进入新测试地图。必须使用这个新地图名，不能继续进入原来的两张地图。
4. 在此前出错的主舞台同一位置转动视角。记录是否仍出现彩色长条、面片错乱，以及舞台物件是否仍显示。
5. 若不再花屏，进一步缩小至本次改变的实体渲染路径；若仍花屏，说明仅切换这些实体的渲染模式不足以解决问题，继续检查实体几何提交等路径。

测试后进入原地图即可恢复原地图效果；也可以删除 `switch/CS16/cstrike/maps/happyvalley_lt_solid.bsp`。无需重装 NSP，无需隐藏实体进行正常游戏。

`build_probe.py` 可从用户参考 ZIP 重建测试地图，`validation.json` 记录源文件摘要、输出摘要、逐实体变化及验证结果。静态验证通过不等于真机花屏已修复。

```sh
python3 build_probe.py 原始参考包.zip 输出目录
```
