# 实体模型渲染兼容性测试 05

这是针对用户所提供、能运行的 FWGS 0.20 自定义 Switch 包的渲染器测试。此前 GPU 同步、多重纹理、NPOT 三项配置均无效；不透明实体测试地图仍花屏；关闭实体绘制后异常消失。当前没有确认唯一根因，也没有 Switch 真机验证结果。

## 安装与测试

1. 完全退出游戏，先备份 SD 卡上的 `/switch/CS16/libref_gl.so`。
2. 只将本包顶层 `switch` 文件夹复制到 SD 卡根目录，覆盖该动态库。无需重装 NSP。
3. 重启游戏，在本地控制台输入 `r_drawentities 1`、`gl_vbo 0`。后者明确选择非 VBO 绘制路径；参考二进制的默认值也是 0，但实际运行值此前未得到确认。
4. 进入原来的 `happyvalley_lt` 或 `happyvalley_lt_fix`，测试主舞台同一位置；不必使用实体不透明测试地图。请确认实体与舞台仍正常显示，再比较是否出现长条和错乱面片。也请对比 `de_dust2`。
5. 若启动异常或没有改善，完全退出，将 `rollback` 目录内的 `switch` 文件夹复制到 SD 卡根目录，恢复参考包原动态库；有自己的备份时优先恢复自己的备份。

不要同时把顶层 `switch` 和 `rollback/switch` 复制到 SD 卡。此包仅适用于上述参考构建，不要用于旧版 2019 静态引擎。

## 改动与检查

仅修改动态库中五条 ARM64 指令，把普通地图面及光照层绘制的 `pglBegin(GL_POLYGON)` 参数改为 `GL_TRIANGLE_FAN`。不改变顶点顺序、纹理坐标、模型矩阵、材质、游戏逻辑、NRO 或动态库接口。该操作是在测试驱动对多边形图元的处理是否相关，并非已经发现并修复着色器错误。

二进制总长度一致，仅 10 个字节不同。已核对各指令所属函数、OpenGL 调用目标和修改前后反汇编；ELF 布局、符号、重定位、其他代码与数据保持原样。地图结构检查中顶点均有限、面边界闭合、各面共面，未发现显著凹多边形，但这些静态检查不能代替实际渲染验证。

`validation.json` 记录每处修改与摘要；`patch_renderer.py` 可从原动态库重建补丁，只接受指定 SHA-256 的参考文件，拒绝对未知版本套用偏移。

```sh
python3 patch_renderer.py 原始libref_gl.so 输出目录/libref_gl.so
```
